# rounds

Расписание дежурств на семестр, нумерация пунктов, добивание неполной команды
до нужного размера, разбивка длинного списка на страницы — задачи разные, а
приём один и тот же: взять из последовательности ровно столько, сколько нужно,
и ни элементом больше.

В модуле `itertools` для этого есть четыре кирпичика, и все они ленивые — не
строят никаких списков и работают даже с бесконечными источниками:

* `count(start, step)` — числа `start`, `start + step`, ... без конца;
* `cycle(items)` — элементы по кругу, снова и снова;
* `repeat(value, times)` — одно и то же значение; без `times` — бесконечно;
* `islice(items, start, stop)` — срез, но для любого перебираемого объекта, а
  не только для списка. У списка есть `items[2:5]`, у генератора и потока
  данных — нет, а `islice` работает с ними всеми.

Первые три сами по себе бесконечны, и пользы от них никакой, пока их не
ограничат четвёртым. `chain` из той же лекции склеивает несколько источников в
один — вместе с `repeat` это даёт «сначала то, что есть, а дальше заполнитель
сколько понадобится».

## Что реализовать

* `duty(people: Sequence[str], weeks: int) -> list[str]` — кто дежурит на
  каждой из `weeks` недель, если дежурят по кругу в порядке списка. Пустой
  список людей даёт пустое расписание, отрицательное число недель —
  `ValueError`;
* `numbered(items: Iterable[str], start: int = 1, step: int = 1) -> list[tuple[int, str]]` —
  пронумеровать элементы: пары «номер, элемент». Номера идут от `start` с шагом
  `step`, в том числе отрицательным;
* `padded(items: Iterable[str], size: int, filler: str) -> list[str]` — ровно
  `size` элементов: недостающие добираются заполнителем, лишние отбрасываются;
* `page(items: Iterable[str], number: int, size: int) -> list[str]` — страница
  номер `number` (нумерация с единицы) при `size` элементов на странице.
  Последняя страница может быть неполной, за концом списка — пусто. Номер
  меньше единицы или размер меньше единицы — `ValueError`.

Все четыре возвращают списки, но внутри лишнего читать не должны: `padded` и
`page` обязаны работать с источником, который никогда не кончится, и не
запрашивать у него ни одного элемента сверх нужного.

`enumerate` для `numbered` не подойдёт: шаг у него всегда единичный. Пара из
`count` и `zip` умеет и это.

## Примеры

```python
people = ["Аня", "Боря", "Вера"]

duty(people, 5)  # ["Аня", "Боря", "Вера", "Аня", "Боря"]
duty(people, 0)  # []
duty([], 5)  # []

numbered(["а", "б", "в"])  # [(1, "а"), (2, "б"), (3, "в")]
numbered(["а", "б"], 10)  # [(10, "а"), (11, "б")]
numbered(["а", "б", "в"], 0, 2)  # [(0, "а"), (2, "б"), (4, "в")]
numbered(["а", "б", "в"], 3, -1)  # [(3, "а"), (2, "б"), (1, "в")]
```

```python
padded(["Аня", "Боря"], 5, "—")  # ["Аня", "Боря", "—", "—", "—"]
padded(["Аня", "Боря", "Вера"], 2, "—")  # ["Аня", "Боря"]
padded([], 3, "—")  # ["—", "—", "—"]

items = ["а", "б", "в", "г", "д"]
page(items, 1, 2)  # ["а", "б"]
page(items, 3, 2)  # ["д"]
page(items, 4, 2)  # []
page(endless(), 3, 4)  # ["8", "9", "10", "11"] — endless() бесконечен
```
