# leaderboard

Таблица рекордов в игре показывает десять лучших результатов. Партий за день
сыграно миллион, и хранить их все, чтобы в конце отсортировать и взять первую
десятку, — расточительство: девятьсот девяносто девять тысяч результатов не
нужны никому уже в момент появления.

Хранить надо ровно десять, и на каждый новый результат отвечать на один вопрос:
лучше ли он худшего из десяти? Значит, из всей таблицы быстро нужен только один
элемент — самый маленький.

Это и есть **куча** (heap): список, устроенный так, что наименьший элемент
всегда лежит в `heap[0]`, а добавление и снятие минимума стоят дёшево. Модуль
`heapq` не заводит отдельного типа — он работает с обычным списком:
`heappush(heap, x)` кладёт, `heappop(heap)` снимает минимум, а
`heappushpop(heap, x)` делает то и другое за одно действие. Порядок остальных
элементов в списке произвольный: куча — не отсортированный список, и печатать
её как есть бессмысленно.

Отсюда приём, который кажется вывернутым наизнанку: чтобы держать `N`
**наибольших** значений, нужна куча минимумов размера `N`. В её вершине лежит
худший из принятых — то есть планка, ниже которой в таблицу не берут.

## Что реализовать

* `top(scores: Iterable[int], count: int) -> list[int]` — `count` наибольших
  результатов по убыванию;
* `worst(scores: Iterable[int], count: int) -> list[int]` — `count` наименьших
  по возрастанию.

Обе работают с одноразовым источником и с `count` больше, чем есть данных;
отрицательный `count` — `ValueError`. В `heapq` для них есть готовые `nlargest`
и `nsmallest`.

Класс `Leaderboard` — таблица, которая живёт в потоке результатов.

* `__init__(self, size: int)` — сколько строк в таблице; поле `size` доступно
  снаружи. Размер меньше единицы — `ValueError`;
* `add(self, score: int) -> bool` — предложить результат. Возвращает, попал ли
  он в таблицу. Пока таблица не заполнена, берут любой; дальше — только строго
  больший, чем нынешняя планка;
* `cutoff(self) -> int | None` — планка, то есть худший из попавших в таблицу.
  У пустой таблицы `None`;
* `best(self) -> list[int]` — содержимое по убыванию, новым списком;
* `__len__` и `__repr__` — `Leaderboard(2, [7, 3])`.

Сортировать всё подряд на каждом `add` нельзя: смысл задачи в том, что таблица
не растёт и одно добавление стоит одинаково дёшево при любом числе результатов.

## Примеры

```python
scores = [2, 8, 5, 1, 6, 7]

top(scores, 3)  # [8, 7, 6]
worst(scores, 3)  # [1, 2, 5]
top(scores, 100)  # [8, 7, 6, 5, 2, 1]
top([], 3)  # []
```

```python
board = Leaderboard(3)
for score in scores:
    board.add(score)

board.best()  # [8, 7, 6]
board.cutoff()  # 6 — планка
len(board)  # 3

board.add(5)  # False — ниже планки
board.add(6)  # False — ровно планка, тоже не берём
board.add(9)  # True
board.best()  # [9, 8, 7]
```

```python
board = Leaderboard(5)
for score in range(10_000):
    board.add(score)

board.best()  # [9999, 9998, 9997, 9996, 9995]
len(board)  # 5 — больше пяти в памяти не лежало ни разу
```
