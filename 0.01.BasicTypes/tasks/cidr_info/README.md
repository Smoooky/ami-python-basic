# cidr_info

Подсеть — это диапазон подряд идущих IPv4-адресов. Записывается он в нотации
CIDR: адрес, косая черта и число — например `192.168.1.0/24`. Число после черты
называется длиной префикса.

Как и в задаче `ip_to_int`, адрес здесь — это 32-битное целое, а четыре числа
через точки лишь его человеческая запись.

## Что означает длина префикса

Длина префикса — это количество **старших** бит, которые одинаковы у всех
адресов подсети. Оставшиеся `32 − префикс` бит различаются: именно они
нумеруют адреса внутри подсети и называются битами узла.

Для `/24` картина такая:

```
   ┌────────────────────────────────┬──────────┐
   │  24 бита префикса — фиксированы │ 8 бит   │
   │  одинаковы у всех адресов сети  │ меняются│
   └────────────────────────────────┴──────────┘
    бит 31                       бит 8   бит 7 … 0
```

Чем длиннее префикс, тем меньше бит остаётся на изменение и тем меньше подсеть.
`/24` оставляет 8 свободных бит, `/26` — уже только 6.

## Три величины, которые нужно вернуть

Все три определяются одними и теми же битами узла:

* **адрес сети** — тот адрес подсети, у которого все биты узла равны нулю; это
  наименьший адрес диапазона;
* **широковещательный адрес** — все биты узла равны единице; это наибольший
  адрес диапазона;
* **количество адресов** — сколько различных значений принимают биты узла.
  Каждый бит удваивает число вариантов.

Биты префикса при этом берутся из адреса, указанного в записи, и не меняются.

## Разбор примера

Возьмём `192.168.1.0/24`. Двоичная запись адреса разбита на префикс и биты
узла:

```
11000000 10101000 00000001 │ 00000000
└──── 24 бита префикса ────┘ └8 бит узла┘
```

Обнулив биты узла, получаем адрес сети — `192.168.1.0`, то есть `3232235776`.
Заполнив их единицами, получаем широковещательный адрес — `192.168.1.255`, то
есть `3232236031`. Восемь свободных бит дают 256 адресов.

Теперь `192.168.1.100/26`. Префикс длиннее, свободных бит только шесть, и
граница проходит внутри последнего байта:

```
11000000 10101000 00000001 01 │ 100100
└──────── 26 бит префикса ────┘ └6 бит┘
```

Биты узла здесь ненулевые: `100100` — это 36. Значит `192.168.1.100` не адрес
сети. Обнулив эти шесть бит, получаем `192.168.1.64`, заполнив единицами —
`192.168.1.127`. Всего адресов 64.

## Краевые случаи

* `/32` — свободных бит нет, подсеть состоит из одного адреса. Адрес сети,
  широковещательный адрес и сам адрес совпадают.
* `/0` — фиксированных бит нет, подсеть охватывает всё адресное пространство:
  от `0.0.0.0` до `255.255.255.255`, то есть 4 294 967 296 адресов.
* Адрес в записи **не обязан** быть адресом сети. Для `192.168.1.7/24` ответ
  будет тем же, что и для `192.168.1.0/24`: лишние биты узла отбрасываются.

## Задача

Реализовать функцию `cidr_info(cidr: str) -> tuple[int, int, int]`,
возвращающую адрес сети, широковещательный адрес и количество адресов — все три
как целые числа в 32-битном представлении.

## Сигнатура

```python
def cidr_info(cidr: str) -> tuple[int, int, int]: ...
```

## Примеры

```python
cidr_info("192.168.1.0/24")  # (3232235776, 3232236031, 256)
cidr_info("192.168.1.100/26")  # (3232235840, 3232235903, 64)
cidr_info("10.0.0.0/8")  # (167772160, 184549375, 16777216)
cidr_info("192.168.1.7/32")  # (3232235783, 3232235783, 1)
cidr_info("0.0.0.0/0")  # (0, 4294967295, 4294967296)
```

Длина префикса — целое число от 0 до 32 включительно. Решение должно работать
без циклов и условий.
