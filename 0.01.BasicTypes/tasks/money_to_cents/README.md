# money_to_cents

## Почему деньги не хранят в float

Вещественные числа в компьютере записаны в двоичной системе, и большинство
привычных десятичных дробей в ней непредставимо точно — как `1/3` непредставима
в десятичной. Вместо `1.15` в памяти оказывается ближайшее двоичное значение,
чуть меньшее или чуть большее.

Для физических измерений такая погрешность несущественна, для денег —
недопустима: ошибки накапливаются при сложении тысяч операций, а расхождение
баланса на копейку означает, что бухгалтерия не сходится.

Поэтому в финансовых системах денежные суммы хранят **целым числом в
наименьшей единице** — копейках, центах. Целые числа в Python произвольной
величины и складываются точно, без потерь.

## Формат записи

На вход приходит сумма, записанная так, как её пишет человек:

* разделителем дробной части может быть как запятая, так и точка;
* пробелы могут встречаться где угодно, в том числе как разделители разрядов:
  `1 234,56`;
* дробная часть может отсутствовать, содержать одну или две цифры;
* перед суммой может стоять минус.

Целая часть присутствует всегда, запись корректна — проверять её не нужно.

## Требование к точности

Результат должен быть **точным для любой корректной записи**. Это не
формальность: наивное преобразование даёт неверный ответ на вполне обычных
суммах. Например, `1.15` после умножения на 100 превращается в
`114.99999999999999`, а `19.99` — в `1998.9999999999998`. Что произойдёт с
такими значениями дальше, зависит от того, каким способом вы получаете целое
число: одни способы отбрасывают дробную часть, другие округляют.

## Задача

Реализовать функцию `money_to_cents(text: str) -> int`, переводящую денежную
сумму из текстовой записи в целое число копеек.

## Сигнатура

```python
def money_to_cents(text: str) -> int: ...
```

## Примеры

```python
money_to_cents("1 234,56")  # 123456
money_to_cents("1,15")  # 115
money_to_cents("1000")  # 100000
money_to_cents("12.5")  # 1250
money_to_cents("0,01")  # 1
money_to_cents("-3,00")  # -300
```
