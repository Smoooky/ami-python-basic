# log_stats

Программы записывают в журнал (лог) сообщения о том, что с ними происходит.
Каждое сообщение снабжается уровнем важности — чтобы при разборе аварии можно
было отделить сообщения об ошибках от обычной болтовни.

Общепринятых уровней несколько; в этой задаче встречаются три:

| Уровень | Смысл |
|---|---|
| `INFO` | обычное событие: сервис запустился, запрос обработан |
| `WARN` | что-то подозрительное, но работа продолжается |
| `ERROR` | операция не удалась |

## Формат файла

Каждая строка файла — одно сообщение. Уровень записан **первым словом**
строки, дальше через пробел идёт произвольный текст:

```
INFO server started
WARN disk usage 91%
ERROR cannot open file
INFO request handled
```

Пустые строки (и строки из одних пробелов) сообщениями не считаются и
игнорируются полностью.

Первым словом может оказаться и что-то другое — лог мог быть повреждён или
содержать уровень, о котором мы не знаем. Такие строки считаются сообщениями,
но ни к одному из трёх уровней не относятся.

## Задача

Реализовать функцию `log_stats(path: str) -> tuple[int, int, int, int]`, которая
читает файл в кодировке UTF-8 и возвращает четыре числа:

1. общее количество сообщений;
2. количество `ERROR`;
3. количество `WARN`;
4. количество `INFO`.

## Сигнатура

```python
def log_stats(path: str) -> tuple[int, int, int, int]: ...
```

## Пример

Для файла, показанного выше, результат — `(4, 1, 1, 2)`.

Обратите внимание, что сумма трёх последних чисел не обязана совпадать с
первым: строки с неизвестным уровнем попадают только в общий счёт.

Файл может быть большим, поэтому читать его целиком в память не следует. Файл
существует, проверять это не нужно. Уровень сравнивается с учётом регистра:
`error` — это неизвестный уровень.
