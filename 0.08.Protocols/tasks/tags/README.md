# tags

В анкете у каждого человека отмечены увлечения: «питон», «бег», «настолки».
Это множество: порядок не важен, повторы бессмысленны, а нужны от такого набора
ровно множественные операции — пересечение (общие увлечения), разность (чем
один удивит другого), включение («ему интересно всё то же, что и ей»).

Абстрактный класс `Set` из `collections.abc` щедрее остальных: за три метода
(`__contains__`, `__iter__`, `__len__`) он отдаёт `|`, `&`, `-`, `^`, все четыре
сравнения на включение, равенство и `isdisjoint`. Но здесь щедрость упирается в
вопрос, которого у `Sequence` и `Mapping` не возникало: результат `a | b` — это
**новый объект вашего класса**, и базовому классу нужно как-то его создать.

## Что реализовать

Класс `Tags` — неизменяемый набор тегов, наследник `Set[str]`.

```python
from collections.abc import Iterable, Iterator, Set


class Tags(Set[str]): ...
```

* `normalize(name: str) -> str` — статический метод: тег обрезается по краям от
  пробелов и приводится к нижнему регистру;
* `__init__(self, *names: str)` — теги перечисляются аргументами:
  `Tags("Питон", "Бег")`. Пустой тег недопустим: `ValueError`. Повторы
  схлопываются;
* `of(names: Iterable[str]) -> "Tags"` — метод класса: создать из готового
  списка, а не из перечисления;
* `_from_iterable(iterable: Iterable[str]) -> "Tags"` — метод класса, делает то
  же самое, но зовёт его базовый класс, а не вы; см. ниже;
* `__contains__`, `__iter__`, `__len__` — перебор идёт в алфавитном порядке;
  проверка вхождения учитывает нормализацию и не падает, если спросили не
  строку;
* `__hash__` — набор неизменяемый, значит его самого можно класть в множество.
  Равным `Tags` считается и обычный `frozenset` с теми же тегами, поэтому и
  хеш должен совпадать с хешем такого `frozenset`;
* `__repr__` — `Tags('бег', 'питон')`, у пустого набора `Tags()`.

Одиннадцать операций из `Set` приезжают готовыми, и **писать их нельзя** —
тесты проверяют, что этих имён нет среди собственных атрибутов класса.
Сравнение при этом работает и с обычным `set`: `Set.__eq__` смотрит на длину и
на вхождение элементов, а не на класс.

## Зачем нужен `_from_iterable`

Операция `a | b` перебирает элементы обоих множеств и собирает из них новый
объект вызовом `self._from_iterable(...)` — это единственная точка, через
которую базовый класс создаёт результаты. По умолчанию она делает
`cls(iterable)`, то есть передаёт весь набор **одним** аргументом. Наш
конструктор ждёт теги перечислением, поэтому получится `Tags(<весь набор>)`:
набор станет одним-единственным тегом, и выглядеть это будет так, будто разом
сломались все операции, хотя `__or__` вы не трогали. Значит, `_from_iterable`
надо переопределить — починив её одну, вы чините сразу все одиннадцать.

## Примеры

```python
anya = Tags("Питон", "Бег", "  настолки  ")
anya  # Tags('бег', 'настолки', 'питон')
"ПИТОН" in anya  # True
42 in anya  # False
Tags("бег", "БЕГ", "  бег  ")  # Tags('бег') — повторы схлопнулись
Tags("Питон", "")  # ValueError

borya = Tags("Питон", "гитара")

anya & borya  # Tags('питон') — общие увлечения
anya | borya  # Tags('бег', 'гитара', 'настолки', 'питон')
anya - borya  # Tags('бег', 'настолки') — чем удивить Борю
anya ^ borya  # Tags('бег', 'гитара', 'настолки')

Tags("питон") <= anya  # True — все теги слева есть у Ани
anya.isdisjoint(Tags("вязание"))  # True — ничего общего

Tags.of(["Питон", "Бег"])  # Tags('бег', 'питон')
Tags("бег") == {"бег"}  # True
{Tags("бег"), frozenset({"бег"})}  # один элемент: наборы равны
```
