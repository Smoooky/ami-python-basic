# toolbox

В чат-боте или в консоли игры есть набор команд: пользователь пишет имя, и
что-то происходит. Связь «имя → функция» надо где-то держать, и заполнять
словарь руками неудобно: команду легко объявить и забыть внести в список.

Декоратор снимает эту заботу — и здесь он раскрывается с неожиданной стороны.
До сих пор декораторы что-то оборачивали. Но никто не обязывает: декоратор
может записать функцию себе в словарь и вернуть её **как была**, ничего не
меняя. Вызов пойдёт напрямую в исходную функцию, а побочный эффект — регистрация
— уже случился в момент объявления.

```python
@commands.register("привет")
def greet(name): ...


greet("Аня")  # обычная функция, никаких обёрток
commands.run("привет", "Аня")  # и она же по имени
```

Так устроены маршруты в веб-фреймворках и фикстуры в pytest. Заодно пригодится
ещё одна вещь: у функции есть `__doc__`, и если описание команды не задали явно,
его можно взять оттуда.

## Что реализовать

* `first_line(text: str | None) -> str` — первая непустая строка текста, без
  пробелов по краям. Для `None` и для текста из одних пробелов — пустая строка;
* `once(func)` — декоратор: функция выполняется один раз, дальше возвращается
  сохранённый результат, а аргументы последующих вызовов не смотрятся вовсе.
  Метаданные сохраняются. У обёртки есть `called: bool` и `reset()`. Упавший
  вызов не считается выполненным — функцию позовут снова.

Класс `Registry` — набор команд.

* `register(name: str, *, summary: str = "")` — параметризованный декоратор.
  Запоминает функцию под именем и возвращает её **неизменённой**. Пустое имя
  (или из одних пробелов) — `ValueError`; повторное использование имени — тоже
  `ValueError`, причём проверяется это ещё до того, как декоратор увидит
  функцию. Если `summary` не задан, описанием становится первая строка
  `__doc__`, а если и его нет — пустая строка;
* `run(name, *args, **kwargs)` — вызвать команду по имени и вернуть результат.
  Неизвестное имя — `KeyError`. Исключение из самой команды уходит наружу;
* `summary(name) -> str` — описание команды; неизвестное имя — `KeyError`;
* `names() -> list[str]` — имена в порядке регистрации;
* `help() -> str` — строки `"имя — описание"` для всех команд в порядке
  регистрации, склеенные `"\n"`. У пустого набора — пустая строка;
* `__len__` и `__contains__`.

Одну функцию можно зарегистрировать под несколькими именами; разные `Registry`
друг о друге не знают.

## Примеры

```python
commands = Registry()


@commands.register("привет", summary="Поздороваться")
def greet(name: str) -> str:
    return f"привет, {name}"


@commands.register("сумма")
def total(*numbers: int) -> int:
    """Сложить числа.

    Складывает всё, что дали.
    """
    return sum(numbers)


greet("Аня")  # "привет, Аня" — функция не изменилась
greet.__name__  # "greet"

commands.run("привет", "Аня")  # "привет, Аня"
commands.run("сумма", 1, 2, 3)  # 6
commands.run("нет такой")  # KeyError

commands.names()  # ["привет", "сумма"]
len(commands)  # 2
"сумма" in commands  # True

commands.summary("сумма")  # "Сложить числа." — взято из __doc__
print(commands.help())
# привет — Поздороваться
# сумма — Сложить числа.

commands.register("привет")  # ValueError — имя занято
```

```python
@once
def setup() -> str:
    """Подготовка."""
    print("готовлю")
    return "готово"


setup()  # печатает «готовлю», возвращает "готово"
setup()  # "готово", ничего не печатает
setup.called  # True
setup.reset()
setup()  # печатает снова
```
