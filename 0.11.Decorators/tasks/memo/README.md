# memo

Функция, которую зовут много раз с одними и теми же аргументами, каждый раз
считает заново. Если считает она долго, а аргументы повторяются, ответы имеет
смысл запоминать: первый вызов вычисляет, остальные достают готовое. Это
называют мемоизацией, и в стандартной библиотеке она есть готовой —
`functools.lru_cache`. Здесь мы напишем свою, чтобы увидеть, из чего она
сделана.

Декоратором может быть не только функция. Класс становится вызываемым, если у
него есть `__call__` — а значит, годится на роль декоратора. Настройки при этом
принимает `__init__`, и запись выходит такой же, как у параметризованного
декоратора:

```python
@Memo(size=100)
def slow(x): ...
```

Сначала создаётся объект `Memo(size=100)`, потом он вызывается — уже с функцией.

Главный вопрос любого кэша — чем считать «теми же аргументами». Ключ строится
из всего, с чем позвали: и позиционных, и именованных. Отсюда следствие,
которое стоит осознать: `f(1, 2)` и `f(1, b=2)` для кэша — **разные** вызовы,
хотя функция получает одно и то же. Так же ведёт себя и `lru_cache`.

## Что реализовать

Класс `Memo`.

* `__init__(self, size: int | None = None)` — сколько записей держать; `None`
  означает «сколько угодно». Размер меньше единицы — `ValueError`;
* `key(*args, **kwargs)` — статический метод: ключ кэша. Позиционные и
  именованные аргументы различаются, а порядок именованных — нет:
  `key(a=1, b=2)` и `key(b=2, a=1)` совпадают. Ключ должен годиться в ключи
  словаря;
* `__call__(self, func)` — собственно декоратор. Возвращает обёртку, которая
  сохраняет метаданные исходной функции и умеет:
  * считать `hits` и `misses` — попадания и промахи;
  * `cache_size()` — сколько записей сейчас лежит;
  * `cache_clear()` — очистить кэш и обнулить счётчики.

Когда записей становится больше, чем `size`, выбрасывается та, что попала в
кэш раньше всех, — независимо от того, как часто её брали. (`lru_cache` в этом
месте умнее: он выбрасывает ту, к которой дольше всего не обращались.)

Результат неудачного вызова не кэшируется: если функция подняла исключение, оно
уходит наружу, а в кэше ничего не появляется. Нехешируемые аргументы —
`TypeError`, и это нормально: кэш на них не рассчитан.

## Примеры

```python
@Memo()
def square(number: int) -> int:
    """Квадрат числа."""
    print("считаю", number)
    return number * number


square(4)  # печатает «считаю 4», возвращает 16
square(4)  # 16, ничего не печатает
square.__name__  # "square"
square.hits  # 1
square.misses  # 1
square.cache_size()  # 1

square.cache_clear()
square.hits  # 0
```

```python
@Memo()
def add(a: int, b: int) -> int:
    return a + b


add(1, 2)  # промах
add(1, b=2)  # тоже промах: ключ другой
add.misses  # 2
```

```python
@Memo(size=2)
def double(number: int) -> int:
    return number * 2


double(1)
double(2)
double(3)  # 1 вытеснен — он пришёл раньше всех
double.cache_size()  # 2
double(1)  # снова промах

Memo(size=0)  # ValueError
```
