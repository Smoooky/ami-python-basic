# Примеры вопросов

Разбор задач курса эти примеры не заменяют: они показывают формат и глубину
ответа, которой ждут. В настоящем билете вопросы другие и в среднем сложнее.

## Понятие — 2 балла

**Что такое кортеж и чем он отличается от списка?**

Ждём: кортеж — неизменяемая последовательность, список — изменяемая; отсюда
кортеж хешируем и годится в ключи словаря, а список нет.

Половина балла — если названа только неизменяемость, без следствий.

---

**Что такое включение (comprehension)?**

Ждём: краткая запись, строящая коллекцию за один проход, вида
`[выражение for имя in последовательность if условие]`; заменяет цикл, вся
задача которого — собрать список.

## Код — 4 балла

**Что выведет этот код и почему?**

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)
```

Ждём: `[1, 2, 3, 4]`. Присваивание не копирует список: `a` и `b` — два имени
одного объекта, поэтому изменение через одно имя видно через другое.

Половина балла — если вывод назван верно, но объяснение сводится к «списки так
работают».

---

**Что выведет этот код и почему?**

```python
print("10" + "20")
print(int("10") + int("20"))
```

Ждём: `1020` и `30`. Плюс для строк — склейка, для чисел — сложение; тип
операндов определяет операцию, неявного приведения строки к числу нет.

## Устройство — 4 балла

**Почему словарь ищет значение по ключу быстрее, чем список — элемент перебором?**

Ждём: словарь — хеш-таблица, позиция вычисляется из хеша ключа и почти не
зависит от размера словаря; список приходится просматривать подряд. Плата —
лишняя память и требование хешируемости ключа.

Половина балла — если сказано «словарь быстрее», без механизма.

---

**Почему изменяемый объект нельзя использовать ключом словаря?**

Ждём: место в хеш-таблице определяется хешем; если объект изменится, хеш станет
другим, и значение больше не найдётся по тому же ключу. Поэтому у изменяемых
типов хеша нет вовсе — ошибка возникает сразу при попытке использовать их
ключом, а не потом.

Половина балла — если сказано «список нехешируем», без объяснения, чем это
грозит.

## Подход — 4 балла

Вопросы этого вида открытые: правильных ответов несколько, и оценивается
рассуждение, а не совпадение с «эталоном».

**Нужно узнать, встречается ли каждое из тысячи слов в списке из миллиона слов.
Как будете это делать?**

Ждём: перевести миллион слов в множество и проверять вхождение по нему — тогда
одна проверка не зависит от размера списка, вместо миллиарда сравнений
получается миллион плюс тысяча. Названная цена: дополнительная память под
множество, слова должны быть хешируемыми, порядок теряется.

Половина балла — если множество предложено, но выигрыш не объяснён, или если
предложен вложенный цикл без оценки стоимости.

---

**Функции нужно передавать набор чисел: иногда список, иногда результат другой
функции, иногда строку файла, разобранную по пробелам. Как описать параметр?**

Ждём: не привязываться к конкретному типу, а работать через перебор и объявить
параметр как `Iterable`. Важная оговорка: если внутри нужен `len` или два
прохода, одного перебора мало — тогда либо требовать последовательность, либо
собрать список внутри функции.

Половина балла — если сказано «принимать список», без обсуждения других
источников данных.
