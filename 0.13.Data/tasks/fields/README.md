# fields

CSV выглядит так, будто разбирается одной строкой. Пока в данных нет запятой,
так и есть:

```python
'Иванов,"Москва, Россия",78'.split(",")
# ['Иванов', '"Москва', ' Россия"', '78'] — четыре поля вместо трёх
```

Задача — написать разбор и запись CSV самому. **Модулем `csv` пользоваться
нельзя** — ни в разборе, ни в записи.

## Правила формата

Формат описан в RFC 4180:

* поля разделяются запятой, записи — переводом строки;
* поле можно взять в кавычки, и тогда запятая и перевод строки внутри него —
  обычные символы, а не разделители;
* кавычка внутри закавыченного поля записывается двумя кавычками подряд;
* кавычки открывают поле только с самого его начала.

## Что реализовать

Имена состояний и `SPECIAL` — набор символов, требующих кавычек, — уже лежат в
шапке модуля.

* `needs_quotes(field)` — нужно ли брать поле в кавычки;
* `quote(field)` — поле, готовое к записи;
* `unquote(field)` — обратная операция для одного поля. Кавычка не закрыта,
  одиночная кавычка внутри закавыченного поля, кавычка в незакавыченном поле —
  `ValueError`;
* `join_row(fields)` — одна запись без перевода строки в конце. Пустой список
  полей — `ValueError`;
* `dump(rows)` — весь текст: каждая запись заканчивается `\r\n`, как требует
  формат. Разное число полей в записях — `ValueError`;
* `parse(text)` — текст, разобранный в записи. Незакрытая кавычка, кавычка не в
  начале поля, любой символ кроме запятой после закрывающей кавычки —
  `ValueError`.

Разбор и запись обратны друг другу: `parse(dump(rows))` возвращает те же
`rows`, а `unquote(quote(field))` — то же поле.

## Краевые случаи

* Пустой текст — ноль записей, а пустая строка внутри текста — запись из одного
  пустого поля;
* запись `[""]` при записи берётся в кавычки: без них она стала бы пустой
  строкой и потерялась;
* `""` — пустое поле, `""""` — поле из одной кавычки;
* концы строк принимаются оба, `\r\n` и `\n`. Возврат каретки без перевода
  строки вне кавычек — `ValueError`, внутри кавычек это обычный символ;
* пробелы значимы: `" a , b "` даёт поля `' a '` и `' b '`.

## Как посмотреть глазами

`demo.py` берёт таблицу с запятой, кавычкой и переводом строки внутри значений
и показывает, что с ней делает наивный разбор и что — ваш. Знак `⏎` помечает
конец строки файла. На оценку не влияет.

```bash
python demo.py
```

## Примеры

```python
parse('Иванов,"Москва, Россия",78')  # [['Иванов', 'Москва, Россия', '78']]
parse("a,b\r\nc,d\r\n")  # [['a', 'b'], ['c', 'd']]
parse("a,,c")  # [['a', '', 'c']]
parse('"две\r\nстроки",b')  # [['две\r\nстроки', 'b']]
parse("")  # []
parse('a,"b""c",d')  # [['a', 'b"c', 'd']]
```

```python
parse('"не закрыто')  # ValueError
parse('a"b')  # ValueError
parse('"a"мусор')  # ValueError
```

```python
needs_quotes("Иванов")  # False
needs_quotes("Москва, Россия")  # True

quote('он сказал "да"')  # '"он сказал ""да"""'
unquote('"он сказал ""да"""')  # 'он сказал "да"'

join_row(["Иванов", "Москва, Россия"])  # 'Иванов,"Москва, Россия"'
join_row([""])  # '""'
dump([["a", "b"], ["c", "d"]])  # 'a,b\r\nc,d\r\n'
dump([["a", "b"], ["c"]])  # ValueError
```
