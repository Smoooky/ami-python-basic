# pointer

JSON Pointer — строка, которая адресует одно место внутри документа JSON:
`/авторы/0/имя`. Описана стандартом RFC 6901; ей пользуются валидаторы схем,
чтобы сослаться на непрошедшее поле, и формат JSON Patch, чтобы описать правку.

Указатель — это ноль или больше токенов, и перед каждым стоит косая черта.
Разбор идёт слева направо: к документу применяется первый токен, к полученному
значению — второй, и так до конца. К объекту токен применяется как ключ, к
массиву — как индекс.

Косая черта разделяет токены, поэтому ключ с косой чертой внутри записывают,
заменив её на `~1`, а саму тильду — на `~0`.

## Что реализовать

Документ — это то, что вернул `json.loads`: объекты, массивы, строки, числа,
`True`, `False` и `None`.

* `escape(token)` — токен, готовый к записи в указатель;
* `unescape(token)` — обратная замена;
* `parse(pointer)` — список токенов с уже снятым экранированием. Пустой
  указатель даёт пустой список. Непустой указатель, не начинающийся с косой
  черты, — `ValueError`. Тильда, за которой стоит не `0` и не `1`, — `ValueError`;
* `resolve(document, pointer)` — значение по указателю;
* `exists(document, pointer)` — есть ли значение по указателю. Сломанный
  синтаксис указателя наружу проходит: это ошибка в программе, а не отсутствие
  данных;
* `set_value(document, pointer, value)` — **новый** документ, в котором по
  указателю лежит `value`. Исходный документ не меняется, и вложенные объекты в
  нём тоже. Пустой указатель — `ValueError`. Отсутствующий ключ объекта
  создаётся, а индекс массива обязан существовать;
* `pointers(document)` — указатели на все значения документа, включая сам
  документ. Порядок: сначала значение, потом то, что внутри него; ключи объекта
  — в порядке документа, элементы массива — по возрастанию индекса.

`resolve(document, pointer)` обязан отработать для каждого `pointer` из
`pointers(document)`.

## Отсутствие и бессмыслица — разные ошибки

* `KeyError` — места нет: у объекта нет такого ключа, у массива нет такого
  индекса;
* `ValueError` — указатель бессмыслен: индекс массива записан не по правилам
  или токен применяют к строке, числу, `None` или `True`.

`exists` возвращает `False` в обоих случаях.

## Краевые случаи

* `""` адресует документ целиком, а `"/"` — значение под ключом `""`;
* индекс массива — только цифры, без ведущего нуля: `0` годится, `00` и `01`
  нет. Токен `-` стандарт отводит под элемент после последнего, для чтения он
  бессмыслен;
* у объекта эти правила не действуют: `"0"`, `"00"` и `"-"` — обычные ключи;
* пустые токены допустимы: `//` — два пустых токена подряд;
* `pointers` от числа, строки или пустого массива даёт `[""]`.

## Как посмотреть глазами

`demo.py` берёт документ с непростыми ключами и печатает рядом с каждым
значением указатель на него. На оценку не влияет.

```bash
python demo.py
```

## Примеры

```python
document = {"авторы": [{"имя": "Иванов"}], "": "пусто", "a/b": 1, "c~d": 2}

resolve(document, "")  # весь документ
resolve(document, "/авторы/0/имя")  # 'Иванов'
resolve(document, "/")  # 'пусто'
resolve(document, "/a~1b")  # 1
resolve(document, "/c~0d")  # 2
```

```python
parse("")  # []
parse("/")  # ['']
parse("/авторы/0/имя")  # ['авторы', '0', 'имя']
parse("авторы")  # ValueError

escape("a/b")  # 'a~1b'
escape("~1")  # '~01'
unescape("~01")  # '~1'
```

```python
resolve(document, "/нет")  # KeyError
resolve(document, "/авторы/9")  # KeyError
resolve(document, "/авторы/01")  # ValueError
resolve(document, "/авторы/-")  # ValueError

exists(document, "/авторы/9")  # False
exists(document, "авторы")  # ValueError
```

```python
changed = set_value(document, "/авторы/0/имя", "Петрова")
resolve(changed, "/авторы/0/имя")  # 'Петрова'
resolve(document, "/авторы/0/имя")  # 'Иванов'

pointers({"a": [1]})  # ['', '/a', '/a/0']
pointers({"a/b": 1})  # ['', '/a~1b']
```
