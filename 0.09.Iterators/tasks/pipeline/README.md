# pipeline

Журнал оценок за семестр — это длинный список строк «предмет, балл». Средний
балл по матану считается в три шага: отобрать нужный предмет, взять из строк
баллы, отбросить незачёты. Каждый шаг проще всего написать функцией, которая
принимает список и возвращает список.

Беда в том, что каждый такой список создаётся целиком. Три шага — три копии
данных в памяти, и это при том, что нужен один-единственный итоговый средний
балл. На журнале курса разница незаметна, на журнале университета — уже нет.

Генератор решает это, ничего не меняя в сборке конвейера. Функция с `yield`
не выполняет ни строчки, пока у неё не попросят первый элемент, и отдаёт
элементы по одному, ничего не накапливая. Соединённые в цепочку генераторы
работают как передача ведра по цепочке людей: каждый берёт элемент у соседа
слева, что-то с ним делает и отдаёт направо. Из-за этого конвейер работает даже
над источником, который никогда не кончится, — лишь бы у него в конце что-то
ограничивало число элементов.

## Что реализовать

Строка журнала — это `Row`, то есть `tuple[str, int]`: предмет и балл.

* `only(rows: Iterable[Row], subject: str) -> Iterator[Row]` — строки нужного
  предмета; название сравнивается точно;
* `scores(rows: Iterable[Row]) -> Iterator[int]` — из строк только баллы;
* `passing(values: Iterable[int], threshold: int) -> Iterator[int]` — баллы не
  меньше порога;
* `first(values: Iterable[Any], count: int) -> Iterator[Any]` — не больше
  `count` первых значений. Лишнего читать нельзя: после `count`-го элемента у
  источника больше ничего не запрашивают;
* `average(values: Iterable[int]) -> float | None` — среднее; для пустого
  источника `None`.

Первые четыре обязаны быть генераторами — тесты проверяют это через
`inspect.isgenerator`. Подойдёт и функция с `yield`, и функция, возвращающая
генераторное выражение: `return (x for x in ...)` даёт ровно такой же объект.
А вот собрать список и вернуть его нельзя.

`average` — не генератор, она возвращает число. Но и ей нельзя пройти по
источнику дважды: `sum(values) / len(values)` не сработает, потому что у
итератора нет длины, а после `sum` в нём уже ничего не осталось. Значит,
считать сумму и количество надо за один проход.

## Примеры

```python
journal = [
    ("матан", 78),
    ("питон", 91),
    ("матан", 45),
    ("история", 60),
    ("матан", 88),
]

list(only(journal, "матан"))  # [("матан", 78), ("матан", 45), ("матан", 88)]
list(scores(journal))  # [78, 91, 45, 60, 88]
list(passing([78, 45, 88], 60))  # [78, 88]
list(first([1, 2, 3, 4], 2))  # [1, 2]

sum(passing(scores(only(journal, "матан")), 60))  # 166
average(scores(only(journal, "матан")))  # 70.33...
average([])  # None
```

```python
def naturals():  # источник, который никогда не кончится
    number = 0
    while True:
        yield number
        number += 1


list(first(naturals(), 3))  # [0, 1, 2]
list(first(passing(naturals(), 5), 2))  # [5, 6]

source = naturals()
list(first(source, 2))  # [0, 1]
next(source)  # 2 — третье значение так и не тронули
```
