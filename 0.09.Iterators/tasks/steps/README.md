# steps

Шагомер записывает число шагов каждую минуту. За сутки это 1440 чисел, за год —
полмиллиона, и ряд получается рваный: то ноль полчаса подряд, потому что человек
сидит на паре, то резкий скачок. Смотреть на такое бесполезно, сначала его
сглаживают и сжимают.

Все четыре операции ниже — про поток, а не про список. Каждая помнит ровно
столько предыдущих значений, сколько ей нужно, и отдаёт результат сразу, как
только он готов. Поэтому все они пишутся генераторами и работают над источником
любой длины, включая бесконечный.

## Генераторная функция не выполняется при вызове

Важная деталь, из-за которой проверка аргументов работает не так, как ожидается.
Тело генераторной функции не выполняется до тех пор, пока у неё не попросят
первый элемент:

```python
def windows(values, size):
    if size <= 0:
        raise ValueError(...)       # эта строка не выполнится при вызове
    ...
        yield ...

windows([1, 2], 0)      # ничего не произошло: получили генератор
next(...)               # вот теперь ValueError
```

Функция с `yield` при вызове только создаёт объект-генератор. Чтобы ошибка в
аргументах вылетала сразу, проверку выносят в обычную функцию, а сам обход — во
вспомогательный генератор, который она возвращает.

## Что реализовать

* `windows(values: Iterable[int], size: int) -> Iterator[tuple[int, ...]]` —
  скользящее окно: все подряд идущие группы по `size` значений. Если значений
  меньше, чем `size`, окон нет ни одного. Каждое окно — кортеж. Размер меньше
  единицы — `ValueError`, **при вызове**, до чтения хотя бы одного значения;
* `averages(values: Iterable[int], size: int) -> Iterator[float]` — среднее по
  каждому окну; считается через `windows`;
* `dedupe(values: Iterable[int]) -> Iterator[int]` — свернуть подряд идущие
  одинаковые значения в одно. Одинаковые, но разделённые другими, остаются
  обоими: `dedupe` убирает соседей, а не повторы вообще;
* `runs(values: Iterable[int]) -> Iterator[tuple[int, int]]` — то же самое, но с
  длинами: пары «значение, сколько раз подряд оно шло». Серия становится
  известна только тогда, когда кончилась, поэтому очередная пара выдаётся на
  один шаг позже, чем в `dedupe`.

Первого элемента, с которым можно было бы сравнить очередное значение, в начале
ещё нет. Отличить «предыдущего не было» от настоящего значения помогает
сторожевой объект из задачи `dig`: `object()` не равен ничему, кроме себя.

## Примеры

```python
list(windows([1, 2, 3, 4], 2))  # [(1, 2), (2, 3), (3, 4)]
list(windows([1, 2], 3))  # [] — окно длиннее, чем весь ряд
list(windows([1, 2, 3], 1))  # [(1,), (2,), (3,)]
windows([1, 2, 3], 0)  # ValueError сразу, без next

list(averages([0, 10, 20, 30], 2))  # [5.0, 15.0, 25.0]

list(dedupe([0, 0, 0, 5, 5, 0]))  # [0, 5, 0]
list(runs([0, 0, 0, 5, 5, 0]))  # [(0, 3), (5, 2), (0, 1)]
```

```python
def alternating():  # бесконечно: 0, 0, 1, 1, 0, 0, 1, 1, ...
    while True:
        yield from (0, 0, 1, 1)


walk = windows(alternating(), 3)
[next(walk) for _ in range(2)]  # [(0, 0, 1), (0, 1, 1)]

walk = runs(alternating())
[next(walk) for _ in range(3)]  # [(0, 2), (1, 2), (0, 2)]
```
