# session

Касса в столовой: кассир пробивает блюда одно за другим и после каждого называет
текущую сумму. Иногда покупатель просит пересчитать заново, иногда уходит от
кассы, ничего не оплатив, а иногда касса зависает. Все четыре исхода — часть
работы, и все четыре должны попасть в журнал: пустой чек, брошенный поднос и
поломка выглядят в отчёте по-разному.

Приёмник из задачи `tally` умел только принимать. Здесь используется полный
набор: снаружи в генератор можно не только присылать значения, но и **бросать
исключения**, а сам он обязан замечать, что его закрывают.

* `gen.throw(ошибка)` возбуждает переданное исключение прямо в той точке, где
  генератор стоит на `yield`. Если генератор его поймает и дойдёт до следующего
  `yield`, работа продолжится, а `throw` вернёт очередное значение. Если не
  поймает — исключение вылетит наружу, а генератор закроется;
* `gen.close()` возбуждает там же `GeneratorExit`. Его можно перехватить, чтобы
  прибраться за собой, но подавлять нельзя: обработчик обязан кончиться `raise`.
  Закрытый генератор больше не работает — `next` на нём даёт `StopIteration`.

Важно, что `close` зовут не только вручную. Он же срабатывает, когда закрывают
генератор, внутри которого работает наш, — а это, в свою очередь, случается,
когда снаружи бросили перебор. Поэтому уборку и пишут в `finally`.

## Что реализовать

Команда кассе — это `Command`, то есть `int | str`: число — цена блюда, строка —
`"пересчёт"`, `"оплата"` или `"сбой"`.

`session(log: list[str]) -> Generator[int, int | None, None]` — сама касса.
Пишет события в переданный список и после каждой цены отдаёт накопленную сумму.

| Событие | Запись в журнал | Что дальше |
|---|---|---|
| первый `next` | `открыт` | отдаёт 0 |
| `send(цена)` | — | отдаёт новую сумму |
| `send(None)` | `оплачен: <сумма>` | генератор завершается |
| `throw(ValueError)` | `пересчёт` | сумма обнуляется, работа продолжается |
| `throw(другое)` | `сорван: <текст ошибки>` | исключение уходит наружу |
| `close()` | `брошен: <сумма>` | генератор закрывается |

Запись `открыт` появляется только при первом `next`, а не при вызове `session`:
до этого тело генератора не выполнялось вовсе.

* `run(commands: Iterable[Command], log: list[str]) -> int` — прогнать команды и
  вернуть последнюю показанную сумму. Если команды кончились, а оплаты не было,
  покупатель ушёл: кассу надо закрыть. После оплаты остальные команды не
  выполняются;
* `totals(prices: Iterable[int], log: list[str]) -> Generator[int, None, None]` —
  ленивая сумма после каждой цены. Если перебор бросят на середине, касса всё
  равно должна закрыться.

## Примеры

```python
log = []
register = session(log)
log  # [] — тело ещё не выполнялось
next(register)  # 0, теперь log == ["открыт"]
register.send(120)  # 120
register.throw(ValueError())  # 0, в журнале "пересчёт"
register.send(50)  # 50
register.close()  # в журнале "брошен: 50"
next(register)  # StopIteration
```

```python
log = []
run([120, 80, "оплата"], log)  # 200, log == ["открыт", "оплачен: 200"]

log = []
run([120, 80], log)  # 200, log == ["открыт", "брошен: 200"]

log = []
run([10, "сбой"], log)  # RuntimeError, log == ["открыт", "сорван: касса зависла"]
```

```python
log = []
walk = totals([10, 20, 30], log)
next(walk)  # 10, log == ["открыт"]
walk.close()  # log == ["открыт", "брошен: 10"]
```
