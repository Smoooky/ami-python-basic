# rollback

Обновление настроек программы — это десяток мелких присваиваний подряд. Если на
седьмом из них данные окажутся кривыми, настройки останутся наполовину новыми и
наполовину старыми, и это худшее из возможных состояний: программа уже не
работает по-старому, но ещё не работает по-новому.

Базы данных решают это транзакцией: либо применяются все изменения, либо ни
одного. Тот же приём можно реализовать поверх обычного словаря — запомнить его
содержимое на входе в блок и вернуть обратно, если внутри что-то упало.
Гарантию «вернуть обратно в любом случае» даёт протокол контекстного менеджера:
`__exit__` вызывается и при нормальном выходе, и при исключении.

## Что реализовать

Класс `Rollback`.

* `__init__(self, target: dict[str, Any], suppress: tuple[type[BaseException], ...] = ())` —
  `target` — словарь, который защищаем; `suppress` — исключения, которые после
  отката гасятся и наружу не выходят;
* `__enter__` — запоминает содержимое `target` и возвращает **сам** `target`, а
  не копию: внутри блока работают с настоящим словарём;
* `__exit__` — если исключения не было, изменения остаются, а `committed`
  становится `True`. Если было — содержимое `target` возвращается к
  запомненному, `committed` остаётся `False`, а исключение гасится тогда и
  только тогда, когда оно попадает под `suppress`;
* атрибуты `committed: bool` и `error: BaseException | None` — успешно ли
  завершился последний блок и с каким исключением.

Один и тот же объект `Rollback` можно использовать несколько раз подряд: каждый
вход делает новый снимок и сбрасывает `committed` и `error`.

**Откат идёт на месте.** Ссылку на словарь мог получить кто угодно до входа в
блок; если при откате создать новый словарь, все остальные владельцы ссылки
останутся с испорченными данными. Восстанавливать нужно содержимое
существующего объекта: `id(target)` до и после блока совпадает. Снимок при этом
поверхностный — если значением лежит список и внутри блока изменить сам этот
список, откат его не спасёт. Это честная цена копирования одного уровня.

**Про возвращаемое значение `__exit__`.** Вернувший `True` объявляет исключение
обработанным, и наружу оно не выходит. Любое ложное значение (в том числе
`None`, которое возвращает функция без `return`) пропускает исключение дальше.
Ошибиться тут легко: достаточно случайно вернуть непустую строку или ненулевое
число, и исключения начнут молча исчезать.

## Примеры

```python
config = {"host": "localhost", "port": 80}

with Rollback(config) as draft:
    draft is config  # True
    draft["port"] = 8080

config  # {"host": "localhost", "port": 8080}

guard = Rollback(config)
try:
    with guard as draft:
        draft["port"] = 9999
        del draft["host"]
        raise ValueError("порт занят")
except ValueError:
    pass

config  # {"host": "localhost", "port": 8080} — как было
guard.committed  # False
type(guard.error)  # ValueError

quiet = Rollback(config, suppress=(KeyError,))
with quiet as draft:
    draft["port"] = 1
    raise KeyError("нет такой секции")  # погашено, наружу не выйдет

config  # {"host": "localhost", "port": 8080}
quiet.committed  # False
```
