# neighbours

Есть список общежитий и список кофеен, у каждого объекта координаты на карте.
Вопросы к такой паре списков всегда одни и те же: до какой кофейни ближе всего
от каждого общежития, какие кофейни в пяти минутах ходьбы, а где с кофе совсем
беда.

В лоб это два вложенных цикла: для каждого общежития пройтись по всем кофейням.
На сотне объектов незаметно, на десятках тысяч — уже нет, а главное, весь этот
код служебный. Броадкаст позволяет обойтись без него.

Идея в одной строке. Массив общежитий имеет форму `(n, 2)`, кофеен — `(m, 2)`.
Добавим каждому по новой оси:

```python
points[:, np.newaxis, :]  # (n, 1, 2)
others[np.newaxis, :, :]  # (1, m, 2)
```

Правило броадкаста сравнивает формы справа налево: 2 против 2 совпадает, 1
растягивается до `m`, `n` растягивается против 1. Разность этих двух массивов
имеет форму `(n, m, 2)` — это разности координат для **каждой пары**. Осталось
возвести в квадрат, сложить по последней оси и взять корень.

## Что реализовать

`Points` — двумерный массив: строка на точку, столбцы — её координаты.
Координат может быть сколько угодно, не обязательно две.

* `check(points, others=None)` — проверка: массив не двумерный или пустой —
  `ValueError`; у двух наборов разное число координат — тоже `ValueError`;
* `distances(points, others)` — матрица `(n, m)`: в клетке `[i, j]` расстояние
  от `i`-й точки до `j`-й. Без циклов;
* `nearest(points, others)` — для каждой точки номер ближайшей из `others`.
  При равенстве — меньший номер;
* `within(points, others, radius)` — булева матрица «расстояние не больше
  радиуса». Отрицательный радиус — `ValueError`;
* `closest_pair(points)` — два номера самых близких друг к другу точек **внутри
  одного набора**, меньший первым. Точек меньше двух — `ValueError`;
* `farthest_from_all(points, others)` — номер точки, у которой **ближайшая**
  из `others` дальше, чем у остальных. То самое «где хуже всего с кофе».
  При равенстве — меньший номер.

В `closest_pair` есть подвох: в матрице расстояний набора до самого себя вся
диагональ — нули, и минимум всегда найдётся там. Диагональ надо исключить —
например, записав в неё `np.inf` через `np.fill_diagonal`. Номер минимума в
матрице `argmin` выдаёт так, будто она вытянута в строку; строку и столбец из
него достают делением с остатком на ширину матрицы.

Исходные наборы точек ни одна функция не портит.

## Примеры

```python
dorms = np.array([[0.0, 0.0], [10.0, 0.0], [0.0, 10.0]])
cafes = np.array([[1.0, 0.0], [9.0, 1.0], [5.0, 5.0]])

distances(dorms, cafes).shape  # (3, 3)
distances(dorms, cafes)[0, 0]  # 1.0
distances(dorms, dorms)  # симметрична, на диагонали нули

nearest(dorms, cafes)  # [0, 1, 2]
within(dorms, cafes, 2.0)[0]  # [True, False, False]
farthest_from_all(dorms, cafes)  # 2
```

```python
points = np.array([[0.0, 0.0], [100.0, 0.0], [1.0, 0.0]])
closest_pair(points)  # (0, 2)
closest_pair(np.array([[0.0, 0.0]]))  # ValueError — пары не из чего составить
```
