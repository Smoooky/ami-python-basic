# Базовый Python — ПМИ 2026 (осень)

Вводный курс Python: язык с нуля, стандартная библиотека, инструменты
разработчика. Задачи сдаются через
[manytask](https://hsemanytask.org) поверх
[SourceCraft](https://sourcecraft.dev).

## Быстрый старт

1. Зарегистрируйся на курсе: [hsemanytask.org](https://hsemanytask.org)
   → «Sign up» → войди через **Яндекс ID** → введи имя, фамилию (как в LMS)
   и **секрет курса** (сообщит преподаватель в чате).
2. После регистрации в твоём аккаунте на SourceCraft появится **личный
   репозиторий-форк** курса
   (`hsemanytask/ami-python-basic-st-26f-<твой-username>`).
   Ссылка на него есть в веб-интерфейсе manytask (кнопка «MY REPO»).
3. Настрой окружение (см. ниже по ОС).
4. Клонируй свой форк, реши задачу, `git push` → CI прогоняет тесты →
   баллы автоматически появляются в manytask.

## Регистрация: подводные камни

- Если у тебя уже есть аккаунт SourceCraft (через Яндекс) — войти можно
  через тот же Яндекс ID; отдельная регистрация не нужна.
- Секрет курса — не пароль, а строка вида `ami-<слово>-<слово>-26f`. Дай знать
  в чате, если тебе её не сообщили.
- Если после регистрации личного репо нет — обратись к преподавателю
  (иногда creation форка тормозит на стороне manytask).

## Git: минимум, чтобы сдавать задачи

Если раньше с git не работали — прочитай этот раздел целиком, дальше он
понадобится в каждой задаче.

Git хранит историю папки с кодом. Твой форк — такая папка на сервере
SourceCraft; ты работаешь с её копией у себя на компьютере и отправляешь
изменения обратно. Отправка изменений и есть сдача задачи: после неё
запускается проверка и выставляется балл.

### Сначала представьтесь

Каждая запись в истории подписана именем и почтой. Пока ты их не задал, git
либо откажется сохранять изменения:

```
Author identity unknown

*** Please tell me who you are.
```

либо — что неприятнее — сам придумает адрес вида
`ivan@MacBook-Air-Ivan.local` и молча запишет его в историю. Такие коммиты
выглядят как присланные неизвестно кем.

Поэтому один раз на компьютере выполни две команды, подставив своё:

```bash
git config --global user.email "you@example.com"
git config --global user.name "Your Name"
```

Почта нигде не проверяется и никуда не отправляется — она просто пишется в
историю. Указывай настоящую: по ней преподаватель понимает, чьи это
изменения. Ключ `--global` означает «для всех репозиториев на этом
компьютере», так что повторять для каждой задачи не нужно.

Проверить, что записалось:

```bash
git config --global --list
```

### Слова, которые встретятся дальше

| Слово | Что означает |
|---|---|
| репозиторий | папка под наблюдением git вместе со всей её историей |
| коммит | одна сохранённая запись в истории: что изменилось, когда и кто автор |
| ветка | линия истории; в курсе всегда одна, `main` |
| удалённый репозиторий | копия репозитория на сервере |
| `origin` | твой личный форк на SourceCraft, туда ты отправляешь решения |
| `upstream` | общий репозиторий курса, оттуда приходят новые задачи |
| индекс | список файлов, которые попадут в следующий коммит |

### Цикл работы над задачей

```bash
git status                     # что изменилось с прошлого раза
git add <путь-к-файлу>         # отметить файл к сохранению
git commit -m "краткое описание"   # сохранить запись в историю
git push                       # отправить историю на сервер
```

Что здесь происходит по шагам:

- **`git status`** показывает изменённые файлы. Полезно вызывать перед каждым
  шагом: git не угадывает, что ты хочешь сохранить.
- **`git add`** добавляет файл в индекс. Без этого шага изменения останутся
  только на диске. Указывай конкретный файл, а не `git add .`: иначе легко
  утащить в историю мусор.
- **`git commit`** записывает содержимое индекса в историю. Сообщение после
  `-m` пишется для людей — «hello_world: реализовал greet» лучше, чем «фикс».
- **`git push`** отправляет накопленные коммиты в твой форк. Только после
  этого запускается проверка и появляются баллы.

Коммитов перед отправкой может быть сколько угодно: `push` отправит все.

### Как приходят новые задачи

Новые наборы задач появляются в общем репозитории курса. Забрать их к себе:

```bash
git fetch upstream        # скачать изменения, ничего не меняя у себя
git merge upstream/main   # влить их в свою рабочую копию
```

Твои решения при этом не пострадают: git меняет только те файлы, которые
трогали авторы курса. Делай это перед началом каждой новой задачи.

### Если git открыл непонятный редактор

Забыл `-m` у `git commit` — git открывает редактор, чтобы ты написал
сообщение. По умолчанию это часто `vim`, из которого неочевидно как выйти:
нажми `Esc`, набери `:q!` и `Enter` — команда отменится, ничего не
сломается.

Чтобы вместо vim открывался редактор попроще:

```bash
git config --global core.editor "nano"
```

### Частые сообщения об ошибках

| Сообщение | Что случилось |
|---|---|
| `Author identity unknown` | не выполнены две команды `git config` выше |
| `nothing to commit, working tree clean` | нечего сохранять: файл не изменён или забыл `git add` |
| `Updates were rejected` | на сервере есть коммиты, которых нет у тебя — сделай `git pull`, затем `git push` |
| `Permission denied (publickey)` | не настроен доступ к SourceCraft, см. раздел про аутентификацию |
| `Please tell me who you are` | то же, что и первая строка таблицы |

Что коммитить не нужно: `.venv`, `__pycache__` и прочий мусор уже перечислены
в `.gitignore`, git их не покажет и не сохранит.

## Как решать задачу

1. Синхронизируйся с публичным репо (там появляются новые задачи):
   ```bash
   git fetch upstream
   git merge upstream/main
   ```

2. Задачи лежат в директориях вида `<группа>/tasks/<название>/`. Например
   `intro/tasks/hello_world/`. Рядом, в `<группа>/lecture/`, лежит ноутбук
   лекции. В директории задачи:
   - `README.md` — условие
   - `<название>.py` — файл с заготовкой, пишешь код сюда
   - `test_public.py` — публичные тесты (можно запускать локально)
   - `.task.yml` — конфиг задачи (не трогать)

3. Пиши код в `<название>.py` — это единственный файл задачи, который нужно
   менять, и его же имя стоит в `allow_change` внутри `.task.yml`. Линтер и
   проверка типов в CI смотрят только на него, остальное берётся из эталона.
   Проверяй локально теми же командами:
   ```bash
   source .venv/bin/activate
   pytest intro/tasks/hello_world/
   cd intro/tasks/hello_world && ruff check hello_world.py && mypy --strict hello_world.py
   ```

4. Отправляй в CI:
   ```bash
   git add intro/tasks/hello_world/hello_world.py
   git commit -m "hello_world: implement greet"
   git push
   ```

5. Посмотри статус пайплайна в SourceCraft:
   `sourcecraft.dev/<твой-репо>` → **CI/CD**. Баллы автоматически появятся
   в веб-интерфейсе manytask через несколько секунд после успешного
   прохождения тестов.

## FAQ

**Тесты локально проходят, а в CI падают.** Скорее всего используешь
другую версию Python. Проверь `python --version` внутри venv — должно
быть `3.14.x`. Также могут быть приватные тесты в CI, которых нет
локально (сюрприз-крайние случаи).

**CI ругается на mypy/ruff.** Даже если тесты зелёные, mypy или ruff
могут заблокировать зачёт. Проверяют они только твой файл решения — тот, что
указан в `allow_change`. Прогоняй их локально перед push.

**Пуш не проходит: permission denied.** Для SSH — проверь `ssh -T ssh://ssh.sourcecraft.dev`
(и `ssh -T -p 443 ssh.sourcecraft.dev` если 22 закрыт фаерволом). Если
ошибка — ключ не добавлен в SourceCraft или SSH-конфиг не подхватил его.
Для HTTPS+PAT — токен мог протухнуть или у него нет `Repository writer` роли.

**Сделал коммит после дедлайна.** Балл автоматически скалируется по
`.manytask.yml` (см. `deadlines.steps`). Скачало 0.5 через неделю после
`start`, 0 после `end`.

**Задача пропала из manytask.** Возможно у неё `enabled: false` в
`.manytask.yml`, или ещё не наступил `start`. Или экспорт из приватного
репо не прошёл — сообщи в чат курса.

**Что-то не работает.** Первое — прочти вывод CI внимательно, там 90%
проблем видно сразу. Второе — спроси в чате курса.

## Контрибьютить в задачи

Нашёл баг или опечатку в условии? Открой Merge Request:
1. `git fetch upstream && git checkout -b fix/<название-фикса> upstream/main`
2. Правишь, коммитишь.
3. `git push origin fix/<название-фикса>`
4. На SourceCraft создаёшь MR в `ami-python-basic-public-26f:main`.
